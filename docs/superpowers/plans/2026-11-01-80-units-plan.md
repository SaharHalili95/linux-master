# 80 Units Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grow Learn mode from 6 units to 80 units that prepare a learner for LPIC-1, RHCSA and LFCS.

**Architecture:**
- Units live as data in classic scripts that push onto the global `COURSE`.
- Answers come from three places:
  - the `shell.js` simulator
  - output recorded in Docker (`prototype/recorded.json`)
  - concept questions
- The app (`prototype/app.js`) renders any unit generically. It gains part headers, exam chips, scroll-to-current, `rec` output cards, scenario bosses and an `exam` node.

**Tech Stack:**
- Vanilla JS as classic scripts, no build step.
- Playwright tests in `tests/`.
- ESLint (`tests/eslint.config.js`).
- Docker for recordings.
- GitHub Actions: `tests.yml` and `pages.yml`.

**Spec:** [docs/superpowers/specs/2026-11-01-80-units-design.md](../specs/2026-11-01-80-units-design.md). The unit list is [materials/curriculum.md](../../../materials/curriculum.md).

## Global Constraints

- **Unit numbers are permanent.** Progress keys are `unitKey(unit, id)`, which returns `u{unit}-{id}`. Never renumber a shipped unit.
- **Every text is `T(he, en)`.** English must not contain Hebrew letters (the content test enforces it).
- **No invented output.** `output` exercises use either `cmd` (run in the simulator) or `rec` (an id in `recorded.json`).
- **Clarity rules from the owner.** Every exercise must follow them:
  - Name the file and say what is in it.
  - "What will it print?" shows the files the command reads.
  - The answer shows the full command with the path.
  - Counting terminals use `ask`.
  - Already-used commands get `known: true`.
  - Nothing scrolls sideways.
- **Unit shape.** 4 lessons of 6-8 exercises, with a `sentence` exercise right after each lesson's first practice exercise (never directly after a `teach` card). Chest after lesson 2, then a boss.
- **Version bump.** Bump `?v=pNN` in `prototype/index.html` on every change to a loaded file.
- **Deploy list.** Every new file `index.html` loads goes on the `cp` line in `.github/workflows/pages.yml`.
- **Style.** No em dashes in any text. Code style matches `units.js`: one exercise per line, minimal comments.
- **Delivery.** One branch and one PR per phase (or half phase).
  - Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - Merge only after `gh pr checks --watch` passes. The owner approved merging (2026-11-01).

## Review Focus

- **Saved progress from units 1-6 must survive.** A learner with `done` up to `u6-boss` opens the new build and lands on `u7-L0`, with nothing lost. Test it in Task 0.2.
- **Long path on a slow phone.** With 80 units the path must still render fast and open scrolled to the current node, not to unit 1. Test it in Task 0.2.
- **A `rec` id missing from `recorded.json`** must fail the content test, never show an empty card. Test it in Task 0.3.
- **English mode on recorded output.** The output is the same and the label is translated. Covered by the content test.
- **Mock exam left halfway.** Quitting an exam must not mark it done or add mistakes. Test it in Task 10.1.
